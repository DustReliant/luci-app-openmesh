## 开工前 10 问（摘要）

1. **解决**：拓扑图此前只表达"连了谁"，不表达"运行得怎么样"——节点离线靠猜（红点与采集失败混淆）、链路质量无分级、采集异常时用户无从判断数据新旧。
2. **原生**：无现成方案；数据全部来自既有 ubus `topology`（m18 Node/Link 模型）+ r21b `batman_collect` 健康字段，**后端零改动、零伪造**。
3. **复用**：6.1/6.2 画布全部机制（布局持久化/Pointer Events/双链路曲线/客户端扇形）原样保留。
4. **自研**：仅前端状态模型与展示规则（纯函数化，可宿主测试）。
5. **交互**：5s 轮询 → 纯函数状态机（四态/质量分级/事件差分）→ SVG/DOM 渲染；视口/布局/选择与状态更新完全解耦。
6. **存储**：布局 localStorage（既有）；短时趋势仅内存环形缓冲（36 样本/链路，10min 未见即弃）。
7. **ubus**：无新方法、无参数变化。
8. **恢复**：RPC 失败保留最后一次有效拓扑 + 横幅提示（一次事件，不重复弹）；恢复即静默刷新，不重置 pan/zoom/nodePos。
9. **测试**：`tests/test_phase63_status.js` 25 项（真实源码 VM 提取）+ 既有 67 项回归。
10. **兼容**：无后端/协议改动；unknown 状态、缺失指标均有显式展示路径。

## 关键设计决定

- **四态节点模型**（`nodeVisualStatus`）：online 绿 / offline **灰**（红色曾经与"采集失败"混淆——采集失败≠离线是本项目铁律）/ degraded 橙 / unknown 灰+问号。online/offline 只来自会话层；unknown 兜底一切非预期值。
- **degraded 必须有持续证据**：`nodeDegradeBad` 要求 online 节点的**每一条带读数的 802.11s 链路** RSSI ≤ -75，且连续 2 个轮询周期（约 10s）才升级为 degraded；单次 RSSI 抖动、指标缺失、batman TQ 差、节点离线都不构成证据。事件日志记录 degraded 进入/退出。
- **质量分级协议相关**（`linkQualityClass`）：802.11s 按 RSSI（≥-60 好 / ≥-75 中 / 更差 差），BATMAN 按 TQ（≥200 / ≥100 / 更差，满 255），Ethernet 仅按存在性（active，不套无线标尺）；**缺失指标=nodata（--，灰）**，与"已知差"（红）严格区分。曲线颜色仍按协议（蓝/紫/灰），质量色只上标签——TQ 与 RSSI 在视觉上永不同标尺。
- **采集健康解耦**（`collectState`）：ok/stale/failed/rpc 四档只驱动状态栏横幅与 batman 链路"·过期"标记；**永不改变节点颜色**（状态模型签名根本没有健康输入，测试 T11 固化此契约）。batman 过期数据期间 802.11s（iwinfo 实时）不受影响。
- **真实迁移才说话**（`diffTopologyEvents`）：快照差分只在 online↔offline、节点/链路出现消失时产出事件；状态持续期间输出恒为空（5s 轮询零刷屏）。事件进 50 条上限日志，状态栏右侧单行 ticker 展示最新一条。
- **选中对象消失**：轮询时选中项不在新快照 → 清除选择 + 显式提示"所选对象已不在当前拓扑中"，绝不保留误导性实时数据。
- **短时趋势（P2）**：topology API 是纯快照（m18 零持久化），无真实历史可读 → 前端每 5s 采 RSSI/TQ 入环形缓冲（36 样本≈3 分钟，链路消失 10min 即弃），详情面板画折线；**采样缺口（>2 个轮询周期）断线呈现，绝不插值**；明确标注"短时采样，非长期历史"。长期历史留给后续独立阶段（需后端持久化，另行立项）。
- **离线节点保信息**：卡片保留最后已知 IP/MAC/型号，半透明 + "离线 N 分钟前"数据龄；详情面板显示 Data Age。

## 已知边界 / 剩余风险

- 链路 `rx_rate`、Ethernet `speed`、BATMAN `next_hop` 当前 API 不提供——字段到位前一律显示 `--`，不造数。
- degraded 阈值（-75dBm × 2 轮）是工程首版，待真机弱信号场景回填校准。
- 事件 ticker 仅单行最新；多事件并发时的历史查看留后续。
- 真机浏览器验收 NOT TESTED（控制器不在可达网络）；上线前需按任务书 §11 在 AX3000T+x86 环境过一遍。
