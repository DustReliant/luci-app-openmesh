# ADR-0003 节点发现采用自定义 UDP 签名广播

- 状态：已接受（2026-10-23）
- 影响版本：V0.1（M2）

## 决策

自定义 UDP 广播/组播发现协议（:7689/UDP，10s±随机抖动），announce 报文整体 Ed25519 签名（含 ts/nonce 防重放），携带 node_id/pubkey/角色/IP/型号/固件/能力集。领养后该节点转由 TCP 会话（:7688）管理。

## 理由

- 发现报文必须可验真伪（LAN 不可信原则），通用发现协议无签名承载
- 可控的超轻量：单包 ≤512B，无需建连即可广播存在

## 被否决的替代方案

| 方案 | 否决原因 |
|---|---|
| umdns（OpenWrt 自带，base 树已确认存在） | 信息承载弱、不可签名、维护状态差、非默认安装 |
| avahi/mDNS 栈 | 内存与 flash 开销大，违反资源约束 |
| LLDP（lldpd 在 base 树存在） | 面向有线拓扑/网管语义，WiFi 关联场景不适配，且不可签名 |
| 仅依赖 TCP 会话互扫 | 无法支撑「未领养节点被发现」这一核心场景 |
