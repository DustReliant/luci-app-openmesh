# ADR-0002 回程组网三模式，切换交给原生 metric

- 状态：已接受（2026-10-23）
- 影响版本：V0.1（模式 A）、V0.2（模式 B 默认）

## 背景

需求目标 7–10：有线/无线回程、自动选择、故障切换。

## 决策

```
模式 A 纯无线:   br-lan ── mesh0 (802.11s, SAE)          ← V0.1 默认
模式 B 有线+无线: br-lan ── bat0 ──┬─ mesh0 (802.11s)    ← V0.2 默认（推荐）
                                  └─ eth
模式 C 纯有线:   br-lan ── eth
```

- **回程自动选择与故障切换完全依赖原生能力**：模式 B 由 batman-adv 链路 metric 实现（每秒 OGM 探测）；本项目只做编排配置与状态展示
- 禁止出现任何自研的链路探测/切换代码（重复造轮子，且必然劣于原生）

## 理由

- 模式 A 直接桥接 802.11s 不产生环路（HWMP 为 L2 路径选择协议），V0.1 零额外依赖
- 有线+无线同时桥接 br-lan 会成环；把 11s 与 eth 同挂 bat0，由 batman-adv 统一承载，天然无环、天然优选有线、天然故障切换——这是 batman-adv 的设计用途
- 模式 B 也是 mesh11sd 社区推荐组网方式

## 后果

- V0.2 依赖：`wpad-mesh-mbedtls` + `kmod-batman-adv`（feeds/routing）+ `mesh11sd`
- 配置生成器必须按模式输出不同 UCI 结构（wireless / network / batman-adv）
- 「Backhaul 优化」在 V0.4 只做展示与建议，不做切换执行

## 被否决的替代方案

- 自研链路监测+脚本切换：探测粒度/收敛速度全面劣于 batman-adv，维护负担高
- STP 桥接方案（11s 与 eth 都桥 br-lan + stp=1）：收敛慢（秒级~几十秒）、拓扑震荡风险
